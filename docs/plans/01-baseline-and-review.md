# 01 — Baseline: make main green and review what was merged

## The request
Not in the lists; it is the precondition for them. The owner said the work was moving too fast and not coming out well.

## Where we are
Read from GitHub on 2026-10-28 (the checks were never read when the PRs were merged):

- **`ci` is red on main** since the "Ops" merge (#254): `golangci-lint` reports `gofmt` on `services/plans-svc/internal/grpcapi/register.go` and `internal/support/support.go`, `errorlint` on `internal/changes/command/pricechange.go:94` (`err != pgx.ErrNoRows`), `staticcheck` QF1001 on `pkg/mailx/resend.go:185`. Local `gofmt -l` had listed the first two and they were ignored.
- **`sdk-php` is red** since the price-change merge (#253): `php-cs-fixer --dry-run` (exit 8) on the PHP models and resources written by hand (the PHP generator, `composer`, is not installed locally, so `php -l` was the only check).
- **`ci` was cancelled** (by the concurrency group) on several merges in a row (#253, #255, #256), so there is no completed run for them.
- **Eleven mock e2e tests fail on main** since the page-header/empty-state change (#243, another session): credit notes ×3, credit pack purchase, geo address, empty-submit forms, members ×3, API key, onboarding. They fail without any of this session's changes.
- The local macOS toolchain cannot link cgo (`-race` is impossible), so CI's `make test` (race detector) has not been run on anything.
- Twenty PRs (#236–#257) were merged in one day, most with a single pass of local tests.

## Gaps
- No review of the merged work as a whole; each PR was judged by its own tests.
- Generated artefacts that CI checks (`make gen` drift, the Python/TS/Go/PHP SDKs, `docs/error-keys.md`) were regenerated by hand each time; drift checks have not been run as CI runs them.
- Local verification does not match CI (lint, race, PHP style).

## Research first
1. List every failing job of the last ~15 runs of `ci`, `sdk-*`, `nightly`, `deploy-console` with the first error of each (`gh run view --log-failed`). Write the list into this plan.
2. Run in a clean checkout the exact commands of `.github/workflows/ci.yml` (and the SDK workflows), in the same container image where one is used. Record which pass.
3. For the eleven e2e failures: find the commit that broke each (bisect on #243's merge) and whether the test or the page is wrong.

## Decisions needed
None, except: may the other session's #243 be corrected (the failing tests are its page changes) or should it be asked first? (The same checkout is used by another Claude session.)

## Work
1. Fix the lint findings (gofmt, errorlint with `errors.Is`, QF1001) and push to main through a PR; confirm `ci` green on GitHub.
2. Run `php-cs-fixer fix` with the project's config (install composer via Docker if needed) on `sdk/php`, commit the result; make the PHP generator runnable in a container so hand-written models are never needed again (`make gen-php`).
3. Fix or update the eleven e2e tests, one commit each with the reason.
4. Add a local `make ci-local` that runs the same lint/test/gen-drift commands as CI (in Docker where needed) and use it before every merge from now on.
5. Review pass over #236–#257: for each PR, read the diff once more for correctness, security and consistency (error keys translated, i18n in six languages, docs updated, tests that assert behaviour not implementation). Write findings into a table in this file; each finding becomes a task in the plan it belongs to.
6. Re-run `nightly` once and read it.

## Done means
- `ci`, `sdk-go`, `sdk-python`, `sdk-typescript`, `sdk-php`, `docs`, `mcp`, `deploy-console` all green on main, seen on GitHub, not assumed.
- `make ci-local` exists and matches CI.
- The review table is written and every finding is assigned.
