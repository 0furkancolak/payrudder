# ADR 0021: Console on Cloudflare Workers static assets

Status: accepted. Supersedes the serving part of [ADR 0015](0015-operator-console-stack.md).

## Context

The console is a static Vue build. nginx served it and forwarded `/gw` to the gateway so the browser used one origin (no CORS, the session cookie stays first-party). Running a container for that is more to operate than the files need, and the product wants a global edge, instant rollbacks and no image to patch.

## Decision

- The console is deployed as a **Cloudflare Worker with static assets** (`web/admin/wrangler.jsonc`, name `payrudder-console`). The platform serves `dist/` directly, with the single-page-app fallback (`not_found_handling`).
- `assets.run_worker_first` lists the only paths that run code: `/gw/*` (what the client calls), `/env.js`, and the gateway routes customers open directly (`/v1/*`, `/auth/*`, `/r/*`, `/healthz`). The Worker (`worker/proxy.ts`) forwards them to `API_ORIGIN` keeping method, body, query, cookies and `Authorization`, drops hop-by-hop headers, overwrites `X-Forwarded-For` with `CF-Connecting-IP`, and does not follow redirects (the Google flow belongs to the browser). The browser sees one origin, so the gateway needs no CORS.
- `/env.js` (`window.__PAYRUDDER__`) is generated by the Worker from its `BRAND_NAME` and `CONSOLE_DEMO` vars, as the nginx template did from the environment.
- Security headers, the Content-Security-Policy (`script-src 'self'` plus the one jsdelivr origin Tesseract's OCR engine is loaded from, phase 54; the console has no inline script) and the one-year `immutable` cache for hashed `/assets/*` come from `public/_headers`.
- nginx, the multi-stage image and the nginx template are gone. Development keeps Vite (dev server and proxy). The container that remains (`web/admin/Dockerfile`, compose `admin-ui`, Railway) runs `vite preview` with the same `/gw` proxy and `/env.js`; it exists for the CI e2e job and the Railway demo, not for production.
- CI: `.github/workflows/deploy-console.yml` builds and runs `wrangler deploy` on a push to `main` under `web/admin` or by hand, only when `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` exist.

## Consequences

- One more platform, and the API must be reachable on the public internet from Cloudflare (`API_ORIGIN`). Protect it as any public API (the Worker adds no authentication).
- **Rate limits by address.** A Worker connects to the gateway from a public address that is not stable, so the gateway's old rule (believe `X-Forwarded-For` only from a private or loopback peer) would count every visitor under the Worker's address. The gateway now also believes the forwarded client address from a trusted proxy, proven in one of two ways: a shared secret, or a network list. The Worker strips any `X-Edge-Auth` and `X-Forwarded-For` the visitor sent, sets `X-Forwarded-For` from `CF-Connecting-IP` and, when the Worker secret `EDGE_AUTH_SECRET` exists, adds `X-Edge-Auth` with it. The gateway compares `X-Edge-Auth` with `PAYRUDDER_TRUSTED_PROXY_SECRET` in constant time (`PAYRUDDER_TRUSTED_PROXY_SECRET` after the rename; at least 32 characters, environment only) and, on a match, counts sign-in, one-time-code, sign-up and public hosted-page limits by the last `X-Forwarded-For` entry. The secret is the recommended proof for Cloudflare because Worker egress addresses cannot be listed. `PAYRUDDER_TRUSTED_PROXIES` (comma separated CIDRs, empty by default) is the alternative for a proxy with a fixed address. `PAYRUDDER_TRUST_FORWARDED_FOR=true` keeps its meaning (any private or loopback peer). A client that reaches the gateway directly cannot choose its bucket: without the secret or a listed address the header is ignored. Treat the secret as a credential: rotate it by setting the new value on the gateway and the Worker together (during the gap the limits fall back to counting the Worker's address, nothing is rejected).
- Worker responses to the API are not cached (`no-store` unless the gateway says otherwise). Request bodies are streamed; Workers limits (body size per plan, CPU time) apply.
- Rollback is `wrangler rollback` or redeploying an earlier commit.
